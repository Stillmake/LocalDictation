# Release

`scripts/release.sh` does the work; this page explains it. Repos, checked out next to this one:

- **this repo**: source. The DMG is built from it; tag the shipped commit here.
- **Stillmake/releases** (`../releases`): GitHub releases hold the DMGs. `localdictation/changelog.json` is the history, edited by hand; `localdictation/version.json` is the in-app feed, generated by `scripts/feed.mjs`.
- **Stillmake/homebrew-tap** (`../homebrew-tap`): `stillmake/tap/localdictation`, if the cask exists.
- **Homepage repo** (optional): builds from `Stillmake/releases`; `release.sh` dispatches its `deploy.yml`.

## Rules worth keeping

- Version and build are what the DMG carries. The script reads them; don't type them anywhere.
- The DMG goes up before anything points at it. `feed`, `site` and `cask` refuse to run until it is published.
- `changelog.json` is the only hand-edited release file.

Everything else is adjustable.

## Usual flow

1. `gh auth status`: the script needs `gh` signed in.
2. Build and notarize `LocalDictation.dmg` into the project root, or pass `--dmg PATH`.
3. Prepend an entry for the DMG to `../releases/localdictation/changelog.json`, creating the file as a one-entry array if needed:

   ```json
   { "version": "1.0", "build": 155, "notes": [{ "title": "New Features", "items": ["…"] }, { "title": "Bug Fixes", "items": ["…"] }] }
   ```

   Notes cover the commits since the previous release's `Commit:` line, or since the previous source tag. Match the voice of the last few entries: what the user can now do or what stopped breaking, sentence case, no trailing period, bugs named by symptom. Committing it yourself is optional; the feed stage commits it with the feed.
4. Tag the shipped commit with the marketing version: `git tag 1.0 <commit> && git push origin 1.0`.
5. `./scripts/release.sh`

## Stages

| Stage | Does | Re-run when done |
|---|---|---|
| `publish` | Creates `localdictation-{version}-{build}` on Stillmake/releases with the DMG; body is the changelog entry plus `Commit:` | no-op; uploads the DMG if the release lacks it; refuses a different DMG under the same tag |
| `feed` | Regenerates `version.json`, commits `localdictation/` only, rebases on `origin/main`, pushes | no-op commit, push only |
| `site` | Dispatches `deploy.yml` in the homepage repo | redeploys |
| `cask` | `../homebrew-tap/scripts/bump.sh localdictation <dmg>` | no-op commit, push only |

When a stage fails, the script prints the `--only` command that finishes the job. Useful variations:

- `--skip cask,site`: a release that only in-app users see.
- `--only feed`: republish the feed after fixing a note.
- `--notes FILE`: publish before the changelog entry is written. The feed stage still needs that entry.
